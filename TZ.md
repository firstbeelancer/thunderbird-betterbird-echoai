# Техническое задание: Расширение **EchoAI** *(альт. название: **BirdAI**)* для Betterbird / Thunderbird

> **Версия ТЗ:** 1.0  
> **Платформа:** Betterbird / Mozilla Thunderbird (ESR 128+ / 140+, WebExtension / MailExtension Manifest V3)  
> **Формат поставки:** XPI-расширение (чистый JS / HTML / CSS без внешних тяжёлых зависимостей)

---

## 1. Цель и концепция

Создать лёгкое, быстрое и приватное расширение для почтового клиента **Betterbird / Thunderbird**, позволяющее подключать внешние нейросети через **OpenAI-compatible API** (Clodex, OpenRouter, CometAPI, OpenAI, Gemini или любой кастомный агрегатор) и использовать ИИ-ассистента для работы с письмами — включая **прямой голосовой ввод напрямую в мультимодальную LLM**.

### Фундаментальный принцип работы и приватность («Только по вызову»)
- **Zero Background Activity:** расширение **никогда** не сканирует почтовый ящик в фоне, не индексирует письма, не делает автоматических запросов при запуске клиента или при открытии письма.
- **Полный контроль пользователя:** нейросеть подключается строго в момент явного вызова (нажатие кнопки ИИ и выбор пункта меню) и получает только тот контекст, который нужен для конкретной выбранной задачи.
- **Локальное хранение:** API-ключи, настройки, профили и промпты хранятся исключительно локально в профиле Betterbird (`browser.storage.local`) и никуда не передаются, кроме выбранного пользователем API-эндпойнта.

## 2. Точки входа и структура меню

Кнопка ИИ-ассистента доступна в двух местах интерфейса Betterbird / Thunderbird:

### 2.1. Окно чтения письма (`message_display_action`)
Кнопка располагается на панели заголовка открытого письма. По нажатию открывается выпадающее меню:
1. **Быстрый ответ**
2. **Чат с ассистентом**
3. **Краткое саммари**
4. **Перевод**

### 2.2. Окно создания / редактирования письма (`compose_action`)
Кнопка располагается на панели инструментов окна «Создать» / «Ответить» / «Переслать». По нажатию открывается выпадающее меню:
1. **Улучшить текст**
2. **Чат с ассистентом**
3. **Быстрый ответ** *(доступно, когда письмо является ответом/пересылкой и имеет контекст переписки)*
4. **Краткое саммари** *(саммари переписки или длинного черновика)*
5. **Перевод**

## 3. Функциональные требования по сценариям

### 3.1. Сбор полного контекста переписки (Thread Context)
Для сценариев **«Быстрый ответ»**, **«Чат с ассистентом»**, **«Краткое саммари»** (и опционально как фоновый контекст для **«Улучшить текст»** при ответе):
- Если письмо одиночное — передаётся только оно (тема, отправитель, получатели, дата, текст).
- Если письмо входит в цепочку (тред) — расширение собирает **всю переписку целиком** в хронологическом порядке (все реплики ветки через заголовки `Message-ID` / `References` / `In-Reply-To` и API тредов + аккуратная очистка и дедупликация вложенных цитат), чтобы нейросеть полностью понимала ход разговора.
- В случае экстремально длинной ветки применяется мягкая защита от переполнения контекстного окна модели (сохраняется начало переписки и максимально возможное число последних реплик, с уведомлением пользователя).

### 3.2. Пункт «Быстрый ответ»
- Открывается компактное модальное окно, где нейросеть **сразу** начинает генерацию готового ответа на письмо с учётом всей переписки и системного промпта («Мой стиль»).
- Отображается живой анимированный статус работы модели и счётчик потраченных токенов.
- **Кнопки действий:**
  - **Вставить в ответ** — в режиме чтения открывает новое окно-черновик ответа (`beginReply`) с уже подставленным текстом **строго выше существующей HTML-подписи Betterbird** (`moz-signature`) и цитаты переписки, не затирая их; в окне Compose вставляет текст прямо в текущее письмо с сохранением HTML-подписи.
  - **Копировать** — копирует готовый текст в буфер обмена (с кратким подтверждением).
  - **Перегенерировать** — запрашивает альтернативный вариант.
  - **Докрутить в чате** — переносит контекст и текущий черновик в «Чат с ассистентом».
  - **Закрыть**.

### 3.3. Пункт «Чат с ассистентом» (модальное окно диалога)
Полноценный многоходовой диалог с ИИ-ассистентом:
- В контекст диалога автоматически загружается вся текущая переписка (при вызове из входящего письма) либо текущий текст черновика и цитируемая ветка (при вызове из окна «Создать» / «Ответить»).
- **Поле ввода внизу окна:**
  - Многострочное текстовое поле (`Enter` — отправка, `Shift+Enter` — перенос строки);
  - **Кнопка микрофона** — запись голосовой заметки и отправка аудио напрямую в LLM (см. раздел 4);
  - **Кнопка отправки (`↑`)** (во время генерации меняется на кнопку **«Стоп»** для отмены запроса).
- **Элементы управления у каждой реплики:**
  - Кнопка **Copy** у **каждого** сообщения — как у реплик пользователя, так и у ответов нейросети;
  - У ответов нейросети дополнительно кнопка **«Вставить в ответ»** (в режиме чтения) / **«Вставить в письмо»** (в режиме Compose).
- **Счётчик токенов (пилюля вида `1 581 tokens ▾`):**
  - Показывает суммарный расход токенов;
  - По нажатию раскрывает детализацию: *Входящие (prompt)* / *Исходящие (completion)* / *Всего за диалог*.
- **Живой анимированный статус нейросети:**
  - Сырые рассуждения модели (reasoning / chain-of-thought) **не показываются** в чате;
  - Вместо них всегда видна плавная анимация и понятный текущий статус: *«Отправляю запрос…» → «Думает…» → «Печатает ответ…»* (с поддержкой SSE-стриминга ответа в реальном времени).
- Кнопка **«Закрыть»**.

### 3.4. Пункт «Улучшить текст» (в окне написания / редактирования)
Ключевой сценарий — не просто проверка орфографии, а **умный рерайт и перевод с бытового/эмоционального (в том числе резкого или нецензурного) языка на этичный, живой, грамотный деловой стиль** без канцеляризмов, при этом **сохраняя реальную суть, твёрдость позиции и адекватный эмоциональный диапазон**.
- **Работа с выделением текста:**
  - Если в окне письма **выделен фрагмент текста** — обрабатывается строго выделенный фрагмент; кнопка **«Заменить выделенное»** подменяет только его.
  - Если ничего не выделено — обрабатывается весь написанный пользователем текст черновика (HTML-подпись `moz-signature` и цитируемое чужое письмо ниже не затрагиваются).
- **Кнопки действий:**
  - **Заменить в письме** (или **Заменить выделенное**);
  - **Копировать**;
  - **Докрутить в чате** (переход в диалог для доп. правок голосом или текстом);
  - **Закрыть**.
- Отображается анимированный статус и счётчик токенов.

### 3.5. Пункт «Краткое саммари»
- Анализирует одно письмо (если оно одиночное) или **всю ветку переписки целиком** (если это тред).
- Выдаёт структурированную выжимку: главная суть, к чему договорились, открытые вопросы, сроки и ключевые цифры.
- **Кнопки:** **Копировать**, **Обсудить в чате**, **Закрыть** + статус и счётчик токенов.

### 3.6. Пункт «Перевод»
- Переводит письмо (или всю ветку) при чтении, либо выделенный фрагмент / черновик при написании.
- В верхней части модалки — быстрый выбор языка перевода (по умолчанию: *Русский* при чтении, *Английский* при написании — настраивается).
- **Кнопки:** **Копировать**, **Заменить / Вставить в письмо** (в режиме Compose), **Закрыть** + статус и счётчик токенов.

## 4. Голосовой ввод (напрямую в мультимодальную LLM)

Без использования отдельных STT-сервисов (Whisper и т.п.) — аудиофайл с микрофона передаётся **напрямую в подключённую большую мультимодальную модель** (например, `gemini-4-hydrogen-high` через Clodex, Gemini, OpenRouter и аналоги).

### Технические требования к голосовому вводу:
1. **Запись аудио:** через `navigator.mediaDevices.getUserMedia({ audio: true })` + Web Audio API внутри окна модалки/чата.
2. **UI записи:** при нажатии на микрофон отображается активный статус записи (таймер + живой индикатор уровня голоса), кнопки **«Отправить»** и **«Отменить»**.
3. **Кодирование:** локальная конвертация записи в компактный **WAV (PCM 16-bit, 16 kHz, mono)** — минимальный трафик (~32 КБ/сек) и максимальная совместимость со всеми OpenAI-compatible API-шлюзами.
4. **Формат отправки:** стандартная мультимодальная часть контента `input_audio` (`type: "input_audio"`, `input_audio: { data: "<base64>", format: "wav" }`) в `/v1/chat/completions`.
5. **Отображение в чате:** отправленная голосовая заметка отображается как реплика пользователя с линейной SVG-иконкой микрофона/аудиоволны, кнопкой воспроизведения и длительностью (`Голосовая заметка · 0:18`), а нейросеть сразу отвечает по делу в контексте переписки.
6. **Разрешение микрофона в Betterbird / Thunderbird:** при первом обращении к микрофону предусмотрен стабильный сценарий выдачи разрешения (в отдельном окне/вкладке расширения, чтобы системный запрос не обрывался, как это бывает в короткоживущих popup).

## 5. Настройки расширения (`options.html`)

### 5.1. Подключение к ИИ (OpenAI-compatible API)
- **Пресеты провайдеров (с автоподстановкой правильного Base URL):**
  | Провайдер | Base URL по умолчанию |
  | --- | --- |
  | **Clodex** | `https://clodex.xyz/v1` |
  | **OpenRouter** | `https://openrouter.ai/api/v1` |
  | **CometAPI** | `https://api.cometapi.com/v1` |
  | **OpenAI** | `https://api.openai.com/v1` |
  | **Google Gemini** | `https://generativelanguage.googleapis.com/v1beta/openai` |
  | **Custom OpenAI-compatible API** | *(свободный ввод пользователем)* |
- **Умная нормализация URL:** расширение само корректно обрабатывает любой вариант ввода (`https://clodex.xyz`, `https://clodex.xyz/v1`, `https://clodex.xyz/v1/chat/completions`) без дублирования `/v1` и поломанных путей.
- **API-ключ:** поле ввода с кнопкой показать/скрыть.
- **Выбор модели двумя способами:**
  1. Автоматическая загрузка всего списка моделей с эндпойнта (`/v1/models`) при валидном ключе + удобный поиск по списку;
  2. Свободный ручной ввод названия конкретной модели (например, `gemini-4-hydrogen-high`).
- **Обязательная кнопка «Протестировать подключение»:**
  - Проверяет разрешение доступа к хосту, валидность URL, валидность API-ключа, загрузку списка моделей и минимальный тестовый запрос к выбранной модели;
  - Выводит понятный человеческий статус: зелёный (подключено, время отклика) или красный с конкретной причиной (неверный ключ, ошибка URL, недоступная модель, нет прав доступа к хосту).
- Поддержка сохранения нескольких профилей подключений с быстрым переключением активного профиля.

### 5.2. Системный промпт («Мой стиль») и промпты действий
- **Общий системный промпт («Мой стиль и правила»):**
  - Единые инструкции о пользователе, тоне общения, запрете канцеляризмов и формате ответов. Подмешивается во все генерации.
  - **Правило подписи:** в Betterbird уже настроена HTML-подпись с полными данными отправителя, поэтому нейросеть **не должна** дописывать контакты, должность или шаблонные блоки подписи — максимум только имя (настраивается в поле «Имя для подписи» / системном промпте).
- **Редактируемые промпты для каждого действия** (с готовыми качественными значениями по умолчанию и кнопкой «Сбросить»):
  - *Быстрый ответ*
  - *Чат с ассистентом*
  - *Улучшить текст* *(дефолт: перевод эмоционального/бытового/резкого текста в этичный, живой деловой формат без канцеляризмов, сохраняя суть, твёрдость позиции и адекватный эмоциональный диапазон)*
  - *Краткое саммари*
  - *Перевод* (+ настройка языков по умолчанию для чтения и написания)

### 5.3. Интерфейс
- Выбор темы: *Системная (Авто)* / *Светлая* / *Тёмная*.

## 6. Дизайн и UX

- **Никакого «нейрослопа» и никаких эмодзи:**
  - В интерфейсе используются **исключительно чистые векторные линейные SVG-иконки** (единая толщина штриха `1.75px`, единая оптическая сетка) — **ноль эмодзи** в кнопках, меню, статусах, заголовках и сообщениях интерфейса.
  - Никаких кислотных фиолетово-розовых градиентов, «магических блёсток» и перегруженных декоративных рамок.
- Чистый, спокойный, выверенный интерфейс по мотивам референса (в духе качественного десктопного приложения):
  - мягкие скругления карточек, полей ввода и кнопок-пилюль (`Copy`, `1 581 tokens ▾`, `Закрыть`);
  - спокойная светлая палитра (`#EEF3F8` / `#FFFFFF` / `#2E5E99` / `#1E293B`) и продуманная тёмная палитра с контрастом не ниже **WCAG AA**;
  - аккуратная акцентная кнопка отправки с линейной стрелкой `↑` в поле ввода чата;
  - чистая типографика (`Inter` / системный sans-serif) и аккуратный рендеринг Markdown в ответах нейросети (списки, жирный текст, цитаты, код);
  - плавные ненавязчивые анимации статусов (*«Отправляю запрос…»*, *«Думает…»*, *«Печатает ответ…»*).
- Стриминг ответов (`stream: true`) для мгновенного отклика и отслеживания статуса в реальном времени.

## 8. Этапы реализации

### Этап 1 — Версия 1.0 (MVP)
1. Каркас расширения (Manifest V3), кнопки в окне чтения и в окне создания письма, выпадающие меню.
2. Страница настроек: пресеты (Clodex, OpenRouter, CometAPI, OpenAI, Gemini, Custom), умная нормализация URL, загрузка моделей + ручной ввод, кнопка «Протестировать подключение», «Мой стиль» и промпты действий.
3. Сбор полной переписки (Thread Context) и извлечение/замена выделенного текста в редакторе Compose (с сохранением HTML-подписи `moz-signature`).
4. Модальное окно со всеми 5 режимами (*Быстрый ответ*, *Чат с ассистентом*, *Улучшить текст*, *Краткое саммари*, *Перевод*), SSE-стримингом, анимированным статусом без вывода сырых рассуждений, кнопками Copy у каждой реплики и счётчиком токенов.
5. Прямой голосовой ввод (запись WAV 16 kHz mono → `input_audio` напрямую в мультимодальную LLM).
6. Тестирование в Betterbird и сборка `.xpi`.
7. **Публичная HTML-страница проекта (`docs/index.html` для GitHub Pages):** аккуратная презентационная страница с описанием возможностей, инструкцией установки, кнопкой скачивания `.xpi` и галереей скриншотов/визуалов интерфейса (в едином чистом стиле без эмодзи).

### Этап 2 — Идеи на будущее (v2.0, вне скоупа v1.0)
- Чтение текстовых вложений (PDF, DOCX, TXT).
- Сохранение истории диалогов с ассистентом по конкретным письмам.
- Горячие клавиши для мгновенного вызова меню и голосовой записи.
